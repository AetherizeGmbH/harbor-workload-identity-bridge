## Critical

### C1 — Harbor rejects every `UpdatePermissions` call: spec edits wedge the CR forever; revocations never reach Harbor

- **Where:** `bridge/controlplane/harbor/client.go:222-239`; consumed at
  `bridge/controlplane/reconciler.go:203-208`.
- **What:** The `PUT /robots/{id}` body sets `ID`, `Description`, `Level`,
  `Duration`, `Permissions` — but **not `Name`**. Harbor's `updateV2Robot`
  enforces name immutability by comparing the submitted name against the
  stored one (`robot$…` on-wire form); an empty name ≠ stored name → **400**
  on every call (verified against goharbor/harbor
  `src/server/v2.0/handler/robot.go` upstream).
- **Impact:** Any `HarborAccess` spec edit (generation bump) hits
  `UpdatePermissions` → `markTransientError` → infinite backoff loop with
  `Ready=False`. Permission **revocations never take effect in Harbor**. The
  test suite can't see it: `fakeHarbor`'s PUT branch ignores `Name`
  (`client_test.go:180-188`), `mockHarbor` accepts anything, and e2e never
  edits a CR.
- **Fix:** Extend `Client.UpdatePermissions` to accept the robot's on-wire
  name and set `body.Name`. The reconciler already holds it
  (`existing.Name` from `GetByName` is the `robot$…` form); pass it through
  verbatim so the ADR-0014 "prefix at the boundary" rule stays intact. Teach
  `fakeHarbor` the name-immutability check, and add a generation-bump stage
  to e2e.

## High

### H1 — Data-plane HTTPS server only runs on the leader; default HA install serves ~50% failures

- **Where:** `bridge/dataplane/server.go:56-70`; defaults at
  `charts/harbor-bridge/values.yaml:48-51`; readiness at
  `bridge/cmd/main.go:142` + `bridge-deployment.yaml:133-136`.
- **What:** `Server` implements `manager.Runnable` but not
  `LeaderElectionRunnable`, so controller-runtime places it in the
  leader-election runnable group. With the chart default (`replicas: 2`,
  leader election auto-enabled), the follower never binds `:8443` — yet
  passes readiness, because `/readyz` is an unconditional `healthz.Ping` on
  the health port. The Service round-robins plugin credential requests into
  a closed port.
- **Fix:** Add `func (s *Server) NeedLeaderElection() bool { return false }`,
  pin it with `var _ manager.LeaderElectionRunnable = (*Server)(nil)` and a
  test. Additionally tie a readiness check to the listener actually being
  bound so this class of bug fails probes instead of serving errors.

### H2 — Changing `spec.serviceAccountRef` leaks the old robot with valid credentials forever

- **Where:** `bridge/controlplane/reconciler.go:107-230`,
  `bridge/controlplane/janitor.go:104-126`.
- **What:** The robot name derives from the *current* SA ref. After an edit,
  only the new robot is managed; the old robot's description still points at
  a live CR, so the janitor skips it (it only deletes on `IsNotFound` of the
  owning HA). The old password (already distributed to kubelets) stays valid
  indefinitely (`Duration=-1`, never rotated again).
- **Impact:** The exact operation that means "revoke the old workload's
  access" silently doesn't revoke.
- **Fix:** In the janitor, when the owning HA exists, also compare the robot
  name against `RobotName(cluster, ha.Spec.ServiceAccountRef.Namespace,
  ha.Spec.ServiceAccountRef.Name)` and delete owned robots that no longer
  match. Add a janitor test for the SA-ref-change scenario.

### H3 — Installer `auto` mode flips to `merge` after first install: spurious kubelet restart on the first re-roll of every node

- **Where:** `installer/run.go:32-43`; masked by
  `installer/run_test.go:228` (`TestRun_AutoResolvesToPatchWithoutFlags`).
- **What:** On self-managed nodes `auto` resolves to `patch` on first
  install. Afterwards, kubelet's cmdline carries the flags pointing at *our
  own* bin/config paths, so every later pass resolves to **merge**. The
  state-file mode mismatch plus YAML normalization of the verbatim-rendered
  config then trigger a restart on a **no-op re-roll**, flip the state file
  to `mode: merge` permanently, and rewrite the chart-rendered config in
  normalized form. **Empirically confirmed** (restarts=2, state
  `mode: "merge"`). Violates ADR-0021's "no-op re-rolls do not restart
  kubelet".
- **Fix:** In auto/merge discovery, treat discovered wiring whose
  `ConfigFile == HostConfigDir/credential-provider-config.yaml` (and/or
  `BinDir == HostBinDir`) as our own patch-mode install and resolve to
  `patch`. Add a second-pass auto test whose fake `/proc` cmdline reflects
  the post-patch flags.

### H4 — Installer kubelet discovery is spoofable from an unprivileged pod

- **Where:** `installer/discover.go:53-81` (`findKubelet` takes the first
  `/proc` entry whose `comm == "kubelet"`, in lexicographic order).
- **What:** The installer runs with hostPID and sees every process on the
  node. Any pod can rename its process to `kubelet` and present crafted
  `--image-credential-provider-*` flags. If its PID sorts first, the
  privileged installer writes the root-owned 0755 plugin binary and a
  partly attacker-shaped merged config to **attacker-chosen host paths**,
  restarts kubelet, and silently does *not* install into the real kubelet.
- **Impact:** Escalation primitive from "can run a pod on the node" to
  "root-owned file writes at chosen host paths + kubelet restart", plus a
  silent install failure. Timing-bound (runs at install/re-roll), but
  re-rolls are routine.
- **Fix:** Require the candidate's PPID to be 1 (or `/proc/<pid>/cgroup`
  outside `kubepods`), and **error on multiple candidates** instead of
  picking the first.

### H6 — Long-running sync container gets a writable host-root mount it never needs

- **Where:** `charts/harbor-bridge/templates/plugin-daemonset.yaml:181-190`

## Medium

### M1 — Secret deletion is not watched: up to ~10h data-plane outage before recovery

- **Where:** `bridge/controlplane/reconciler.go:68` (`Owns(&corev1.Secret{})`).
- **What:** `writeRobotSecret` sets labels but no ownerReference (it can't:
  cross-namespace ownerRefs are invalid — HA in tenant ns, Secret in bridge
  ns), so the `Owns` watch maps zero events. A deleted robot Secret goes
  unnoticed until the ~10h cache resync while status stays `Ready=True`.
- **Fix:** Replace with `Watches(&corev1.Secret{}, handler.EnqueueRequestsFromMapFunc(...))`
  mapping via `LabelHarborAccessNamespace`/`LabelHarborAccessName` (Secret
  cache is already scoped to the bridge namespace).

### M2 — Password rotation has no trigger of its own; "daily" rotation actually happens at 24h–34h and only via resync

- **Where:** `bridge/controlplane/reconciler.go:466-507` (`markReady`
  returns `ctrl.Result{}`).
- **What:** `passwordIsStale` only runs when something else reconciles; in
  steady state that's the default 10h SyncPeriod. ADR-0003's daily rotation
  currently rides on an implicit, unpinned controller-runtime default; tune
  or disable SyncPeriod and rotation stops entirely.
- **Fix:** `markReady` should return
  `RequeueAfter: LastRotated.Add(PasswordRotationInterval).Sub(now)` with a
  small floor and jitter.

### M3 — HarborAccess names >63 chars make the reconciler loop forever on Secret creation

- **Where:** `bridge/controlplane/reconciler.go:449-456`
  (`LabelHarborAccessName: ha.Name`).
- **What:** Label values cap at 63 chars; HA `metadata.name` may be up to
  253 (CRD doesn't constrain it). The Secret *name* has an overflow path
  (`labels.go:54-71`), the label does not — apiserver rejects the Create,
  and the CR retries forever.
- **Fix:** Hash-truncate the label value the same way the name is handled
  (keep `secretOwnedByOtherHA`'s comparison symmetric), or constrain HA name
  length in the CRD.

### M4 — 409-recovery adopts a robot without applying the CR's permissions

- **Where:** `bridge/controlplane/reconciler.go:270-301`
  (`recoverExistingRobot`).
- **What:** Recovery rotates the password and calls `markReady`
  (`ObservedGeneration = Generation`), so an adopted robot with divergent
  permissions reports Ready with wrong Harbor grants, and no later pass
  corrects it.
- **Fix:** Call `UpdatePermissions` with the desired description/perms in
  the recovery path before `markReady` (depends on C1's fix).

### M5 — Installer quote-stripping can corrupt `KUBELET_EXTRA_ARGS` and break kubelet start

- **Where:** `installer/defaultkubelet.go:41-43`
  (`strings.Trim(val, "\"'")`).
- **What:** `Trim` strips *any number* of leading/trailing quote characters,
  not one matched pair, and `strings.Fields` splits inside quoted args. An
  inner-quoted value like
  `--register-with-taints="x:NoSchedule"` becomes unbalanced, gets
  re-wrapped, and systemd's EnvironmentFile parse mangles the args — kubelet
  can fail to start after the installer's restart (node breakage).
- **Fix:** Strip exactly one matching outer quote pair; add tests with
  inner-quoted and quote-terminated values.

### M6 — No post-restart verification: a broken or never-wired node reads as successfully installed

- **Where:** `installer/restart.go:19-27`, `installer/run.go:164-187`.
- **What:** `systemctl restart` returns 0 even if kubelet crash-loops
  immediately (e.g. strict config rejection) or the unit never sources
  `/etc/default/kubelet` (flags silently not applied). Success state is
  persisted and never revisited — contra ADR-0021's "fail loudly, never
  half-install".
- **Fix:** After restart, poll `systemctl is-active <unit>`; in patch mode
  re-discover the kubelet cmdline and confirm the flags are live; exit
  non-zero otherwise.

### M7 — `tls.enabled=false` deadlocks every pod on a Secret that is never created

- **Where:** `charts/harbor-bridge/templates/bridge-deployment.yaml:158-160`,
  `plugin-daemonset.yaml:134-140` vs `values.yaml:31-34` (pre-existing, not
  introduced by the current diff).
- **What:** The mesh-sidecar topology is advertised as supported, but both
  workloads unconditionally mount the `<fullname>-tls` Secret, which only
  exists when `tls.enabled=true` (`bridge-certificate.yaml:1`). All pods
  hang in ContainerCreating; the installer would also fail reading
  `/tls/ca.crt` (`installer/run.go:21`).
- **Fix:** Gate the tls volume/env/CA plumbing on `tls.enabled`, or document
  the pre-created-Secret requirement and add a required-value gate.

### M8 — Hardening regression vs the old pause container: no `drop: [ALL]`, no seccomp profile

- **Where:** `charts/harbor-bridge/templates/plugin-daemonset.yaml:92-94,
  107-111`.
- **What:** The non-privileged containers (sync always; install in `none`
  mode) run as UID 0 with default capabilities; the replaced pause container

### M9 — k3s support claim is false; `mode: auto` crash-loops the DaemonSet on k3s

## Rating

| Layer | Grade | One-line justification |
|---|---|---|
| `bridge/` (control+data plane) | **A-** | Disciplined, invariant-driven, exceptional why-comments and behavior-pinning tests; docked for speculative harbor-package surface and the avoidable cross-package naming duplication. |
| `plugin/` | **A-** | Minimal and contract-focused; docked for one dead constant, untested TLS plumbing, non-injectable retry sleep. |

**Overall: A-.** The foundations are genuinely excellent for a pre-release
project — the comment culture (why-comments with ADR/issue provenance), the
invariant-pinning test style, and the CI gate discipline are what most teams
aspire to and don't reach. What keeps it off a flat A is consistent across
layers: speculative surface nothing calls yet (env knobs, interface methods,
Terraform variables "for later"), and transition sediment from the in-flight
ADR-0021 refactor that the tombstone discipline caught in values but not in
NOTES.txt/SECURITY.md/e2e docs. Both classes are cheap to fix and neither is
structural. The one quality item worth prioritizing alongside the bug fixes
is the duplicated Secret-naming logic between control and data plane — it's
the same hand-sync risk ADR-0015 accepts deliberately for the plugin, except
here no ADR requires it.
