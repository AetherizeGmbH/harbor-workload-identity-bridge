NEXT STEPS

  1. Verify the bridge came up (every replica serves credentials):

       kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ include "harbor-bridge.bridge.fullname" . }}
       kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "harbor-bridge.bridge.fullname" . }} -c bridge

{{- if .Values.plugin.enabled }}

  2. Verify the plugin landed on every node:

       kubectl -n {{ include "harbor-bridge.plugin.namespace" . }} rollout status ds/{{ include "harbor-bridge.plugin.fullname" . }}
       kubectl -n {{ include "harbor-bridge.plugin.namespace" . }} logs ds/{{ include "harbor-bridge.plugin.fullname" . }} -c install
{{- if eq .Values.plugin.install.mode "auto" }}

     install.mode=auto: on each node the installer inspects kubelet. If kubelet
     already runs with --image-credential-provider-* flags (EKS / GKE / AKS node
     images) it MERGES our provider into that config; otherwise it PATCHES
     /etc/default/kubelet. Kubelet is restarted once per node — only when the
     effective config changed — and verified healthy afterwards. Running
     containers are not affected by a kubelet restart.
{{- else if eq .Values.plugin.install.mode "merge" }}

     install.mode=merge: the installer adds our provider to the credential-
     provider config kubelet already uses{{ if .Values.plugin.install.configFile }} ({{ .Values.plugin.install.configFile }}){{ end }}
     and restarts kubelet once per node when that config changed.
{{- else if eq .Values.plugin.install.mode "patch" }}

     install.mode=patch: the installer writes the plugin to
     {{ .Values.plugin.hostBinaryDir }}, its config to
     {{ .Values.plugin.hostConfigDir }}/credential-provider-config.yaml,
     adds the two flags to KUBELET_EXTRA_ARGS in /etc/default/kubelet, and
     restarts kubelet once per node when anything changed.
{{- else }}

     install.mode=none: the installer only copies files. KUBELET IS NOT TOUCHED —
     until you add these flags to every kubelet, the plugin is never invoked and
     pulls fall back to anonymous:

       --image-credential-provider-bin-dir={{ .Values.plugin.hostBinaryDir }}
       --image-credential-provider-config={{ .Values.plugin.hostConfigDir }}/credential-provider-config.yaml
{{- end }}
{{- else }}

  2. Install the plugin on every node yourself (plugin.enabled=false). Kubelet
     needs the plugin binary and this provider entry in the credential-provider
     config it reads (--image-credential-provider-config). The binary is in the
     plugin image at /plugin/harbor-bridge-plugin; install it in kubelet's
     --image-credential-provider-bin-dir as {{ include "harbor-bridge.plugin.providerName" . }}
     (kubelet runs the binary named like the entry):

       {{ include "harbor-bridge.plugin.image" . }}

     Provider entry (put the bridge CA — ca.crt of Secret
     {{ include "harbor-bridge.tlsSecretName" . }} — on the node at the
     HARBOR_BRIDGE_CA_BUNDLE path, or inline the PEM as its value):

       - name: {{ include "harbor-bridge.plugin.providerNameYAML" . }}
         apiVersion: credentialprovider.kubelet.k8s.io/v1
         matchImages: ["<your Harbor host>"]
         defaultCacheDuration: {{ .Values.plugin.defaultCacheDuration | quote }}
         env:
           - name: HARBOR_BRIDGE_ENDPOINT
             value: {{ include "harbor-bridge.plugin.bridgeEndpoint" . | quote }}
           - name: HARBOR_BRIDGE_CA_BUNDLE
             value: {{ include "harbor-bridge.plugin.hostFile" (list . "ca.crt") | quote }}
{{- if .Values.plugin.bridgeEndpoint }}
{{- if .Values.tls.enabled }}
           - name: HARBOR_BRIDGE_SERVER_NAME
             value: "{{ include "harbor-bridge.bridge.fullname" . }}.{{ .Release.Namespace }}.svc"
{{- else }}
           # - name: HARBOR_BRIDGE_SERVER_NAME   # a name your certificate carries,
           #   value: "<name>"                   # unless it names the endpoint's host
{{- end }}
{{- end }}
         tokenAttributes:
           serviceAccountTokenAudience: {{ .Values.plugin.audience | quote }}
           requireServiceAccount: true
           cacheType: ServiceAccount

{{- if contains "$(NODE_IP)" (include "harbor-bridge.plugin.bridgeEndpoint" .) }}

     Replace $(NODE_IP) with a concrete address: only the chart's installer
     substitutes it, and kubelet passes the value to the plugin unchanged.
{{- end }}
{{- if and .Values.plugin.bridgeEndpoint .Values.tls.enabled }}

     HARBOR_BRIDGE_SERVER_NAME makes the plugin verify the bridge certificate
     against the bridge Service's name, because the certificate does not name a
     node IP or a load balancer.
{{- end }}

     Talos: see docs/install-external-plugin.md in the repository.
{{- end }}

  3. Apply a HarborAccess CR (see config/samples/ in the repo). Its
     spec.trustPolicy.audience must equal:

       {{ .Values.plugin.audience }}

     and its spec.trustPolicy.issuer must equal (byte for byte):

       {{ .Values.bridge.oidcIssuer }}

  4. Uninstalling: delete your HarborAccess objects BEFORE `helm uninstall`.
     Each carries a finalizer that revokes its Harbor robot; without the
     bridge running, those deletions (and the deletion of their namespaces)
     wait forever. If that already happened, reinstall the bridge — or remove
     the "{{ include "harbor-bridge.finalizer" . }}" finalizer by hand and delete the leftover
     bridge-{{ .Values.clusterName }}.* robots in Harbor.
{{- if .Values.plugin.enabled }}
     `helm uninstall` leaves the kubelet provider entry {{ include "harbor-bridge.plugin.providerName" . }}
     and its files on the nodes; README "Uninstalling" shows how to remove them.
{{- end }}
